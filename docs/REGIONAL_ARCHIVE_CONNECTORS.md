## Source connector acceptance checklist

1. **Rights and access:** identify service owner, exact API path, documented usage terms, query key/permissions, record visibility, rate limit, redistribution and living-person policy.
2. **Safe request:** fixed whitelisted HTTPS domain, no redirects to arbitrary hosts, bounded timeout, response size, paging, retries and rate limits; user explicitly authorizes external name/locale transmission.
3. **Real response:** independently observe a permitted live query with identifiable published record URL and stable ID; record response schema variation and errors **without logging real private search queries to GitHub**.
4. **Provenance:** preserve provider, title/name as written, date/place as written, collection/call number if supplied, URL, access status, query time, and source independence group. Keep copied editions grouped.
5. **Honest result states:** not searched, blocked for credentials, refused, rate limited, unavailable, no hits, partial, and results. No synthetic or guessed individuals as retrieved matches.
6. **Review only:** never create person/parent claims or merge identities from a catalog hit. Require manual original-record inspection to upgrade evidence; catalog description alone is a lead.
7. **Test suite:** offline fixtures for authentic permitted schema and malicious/empty/duplicate responses, plus a separate live smoke only when an approved key/connection is available.

- **Record comparison:** the separate `src/kinship/matching.py` helper generates review signals only (name mention and provenance caution). It never assigns a probability of identity or upgrades case claims. Connecting it to the UI is another backlog item.

**Do not confuse metadata search with archival evidence verification.** Search/citation rights may differ from image/download rights; a family tree entered by another user is not an original archival record.
