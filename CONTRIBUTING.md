# Contributing

Please open a scoped issue before adding a new region or a third-party component.

1. Add publicly verifiable, authoritative links for archive leads; note last verified date and access limitations.
2. Preserve every original document text, date and script; generated translations are supplemental and marked as such.
3. Extend the standard library tests; run `python -m unittest discover -s tests -v` locally. GitHub Actions are optional and not required.
4. Include only synthetic samples. Do not paste real family information into issues, PR descriptions or CI logs.
5. Do not scrape, send archive emails or upload genealogical materials automatically.
6. Preserve LICENSE and attribution for new third-party software. CC-BY-NC-SA material must not be copied into MIT modules.
7. Audit failures block report generation. Structural success never equals genealogical proof.

Pull requests should state the impacted region, new evidence assumptions, privacy implications, license check and local test summary. Reviewers can request changes but should not make autonomous factual approvals of kinship.
